这个需求做了什么

以前远程的 claude 只能以终端界面跑在 xterm 里，权限确认、计划审阅、选项提问都要在终端里用键盘操作，长输出和 diff 也不好读。现在新建会话时可以选「终端」或「对话」：终端会话和以前一样；对话会话由远程的 daemon 以 stream-json 方式驱动 claude，桌面端显示成对话界面——流式消息和 Markdown、带 diff 的工具块、可以直接回答的权限 / 计划 / 提问卡片，以及中断、忙时排队、斜杠命令、权限模式切换。

桌面端断线后对话会话在远程照常运行，重连后按顺序补齐漏掉的消息，没答的权限请求还在等你。侧边栏的点（灰：有新消息，绿：回合结束，黄：等你处理）不需要配置 hook，等你处理时发桌面通知。对话不够用时可以「新建终端会话接上」同一段对话。协议版本从 2 升到 3。

截图里的 claude 是测试用的假 claude，所以消息内容是 tool Edit、done Bash 这样的测试文字。

合并前建议知道的已知问题

都不拦合并，按对你的影响从大到小排。

1

正在别处打字时来了权限请求，敲的 1 会直接允许它

权限卡片一出现就把键盘拿走，而卡片上单个数字键就是回答（1 = 是）。所以你正在对话输入框里打字、或在「机器」对话框里填地址时，如果当前会话来了权限请求，接着敲的 1 不会进输入框，而是允许了那条命令。对话框开着时卡片被遮罩盖住，更不容易发现。

这是第 1 轮就有的设计（和 Claude Code 在终端里的权限提示接管键盘一致），这一版不改；建议合并后第一个修。改名输入框不受影响（返工时已挡住，这一轮验证过）。

依据：verdict.md 界面部分 B 节第 4 行、H 节、备注 1 / 2；decisions d15；tasks.md「后续」第一条（含两个改法）

2

用鼠标点按钮、或用「否 + 说明」回答后，要再点一下输入框才能打字

按 1 / 2 / Esc 回答卡片后可以直接接着打字。但用鼠标点卡片上的按钮、用「否」并写说明、或提交提问卡片之后，键盘不在任何地方，要先点一下输入框。字不会进错地方，只是多点一下；不比修之前差。

依据：verdict.md 界面部分「问题 1」、K 节；decisions #54

3

改名中直接点另一个会话，那一下可能没反应

名字会保存，但不会切过去，再点一次即可。daemon 在本机或离得近（网络往返 20 ms 左右）时，按正常的手速点基本每次都会遇到；往返 50 ms 左右时有时无；离得远（往返 100 ms）反而不会。这是改动前就有的问题（侧边栏在按下和松开之间刷新，把这次点击吞了）。

依据：verdict.md 界面部分 E 节、备注 3；tasks.md「后续」

4

历史文件极多极大时，带 -c 新建可能要等几十秒

正常数据下查找「这个目录最近一次对话」是毫秒到几百毫秒。验证者造了一份极端数据（80 份各约 50 MiB 的历史，都不属于这个目录）时，一次新建等了约 23 秒，结果是对的；等待期间其它会话不受影响。

依据：verdict.md 非界面部分「X9 耗时与会话隔离」、备注 1；decisions #55

5

其余 21 条小问题和改进记在 tasks.md「后续」

「后续」现在共 25 条，上面 4 条之外还有 21 条，都是体验上的小处或测试自身的改进。例如：拒绝后的工具块标的是「失败」而不是「已拒绝」；已结束的对话会话在侧边栏没有标记；上滑阅读时没有「下面有新内容」的提示；状态点只靠颜色区分；卡片有焦点时没有可见的外框；长对话的页面元素不回收。

依据：tasks.md「后续」
