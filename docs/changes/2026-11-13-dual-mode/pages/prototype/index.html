问题定位

reconcileTmuxSessions 在持有 Manager.mu 时调用 applyTmuxSessionMetadata 改写 Runner 的 workdir / name，而 Runner.CurrentWorkdir() 只持 metaMu 读——两边不是同一把锁，List() 与 Attach() 并发时就会报 DATA RACE。

修复思路：

  1. 写元数据时同样持 r.metaMu（保持锁顺序 Manager.mu → Runner.mu → Runner.metaMu）
  2. 新增 TestReconcileConcurrentList：16 个 goroutine 并发 List + Attach
  3. 补一条断言：tmux 里已不存在的幽灵会话会被删除

func TestReconcileConcurrentList(t *testing.T) {
	m := newTestManager(t)
	seedTmuxSessions(t, m, "a", "b", "c")
	var wg sync.WaitGroup
	for i := 0; i < 16; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			_ = m.List()
			_, _ = m.Attach("a", 80, 24) // 与 reconcile 争用 Runner 元数据
		}()
	}
	wg.Wait()
}

对话模式照搬插件的交互工具块可折叠（输入 / 输出），Edit 显示行内 diff；权限确认替换输入框，给出选项和「告诉 Claude 换个做法」；提问和计划以卡片展示。

侧边栏圆点灰 = 有新输出 · 绿 = 空闲 · 黄 = 等待确认。对话会话直接由事件流得出状态，终端会话仍靠 hook。
