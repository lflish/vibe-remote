X9：`-c` 查找「该目录最近一次对话」的耗时实测（2026-11-20，本机 darwin/arm64，Go 1.26.2，不带 -race）

方法：一个临时的 Go 测试（不提交）在 /tmp 下自己的目录里生成 JSONL，对 chat.LatestSessionForWorkdir
连续调用 5 次取最快 / 最慢。每条记录是 claude 的 assistant 记录的形状（parentUuid、sessionId、message.content…），
没有 `cwd` 键的记录就是去掉这个键。文件刚写完，都在页缓存里（没有清缓存的权限，冷盘读取没有测；
50 MiB 在 SSD 上的顺序读一般是几十毫秒）。

一、最终实现（逐行读到第一个 cwd；不含 "cwd" 字样、也没有 \u 转义的行不做 JSON 解析；回退扫描跳过自己的项目目录）

50 MiB，cwd 在最后一行，每行约 300 字节                         找到    最快 37.3 ms  最慢 38.5 ms
50 MiB，完全没有 cwd，每行约 300 字节                           没找到  最快 39.3 ms  最慢 40.1 ms
50 MiB，cwd 在最后一行，每行约 2000 字节                        找到    最快 31.2 ms  最慢 31.9 ms
50 MiB，完全没有 cwd，每行约 2000 字节                          没找到  最快 31.0 ms  最慢 32.5 ms
50 MiB，cwd 在最后一行，每行约 20000 字节                       找到    最快 28.5 ms  最慢 31.3 ms
50 MiB，完全没有 cwd，每行约 20000 字节                         没找到  最快 27.6 ms  最慢 29.8 ms
一个目录 200 份历史（每份 1 MiB），最新 199 份属于别的目录、cwd 在第 1 行，自己的是最旧的一份
                                                                找到    最快 14.8 ms  最慢 24.0 ms
同上，但那 199 份的 cwd 都在最后一行（要读完 199 MiB）          找到    最快 153.7 ms 最慢 163.6 ms
同上，但那 199 份完全没有 cwd（要读完 199 MiB）                 找到    最快 154.2 ms 最慢 157.4 ms

二、对照：同样去掉行数上限，但每一行都做 JSON 解析、回退扫描不跳过自己的项目目录（修复的第一版，没有提交）

50 MiB，cwd 在最后一行（300 / 2000 / 20000 字节的行）           295.3 / 257.9 / 242.4 ms
50 MiB，完全没有 cwd（同一份文件被目录扫描和回退扫描各读一遍）  590.8 / 517.7 / 483.7 ms
200 份历史，199 份 cwd 在第 1 行                                15.0 ms
200 份历史，199 份 cwd 在最后一行                               1.078 s
200 份历史，199 份完全没有 cwd                                  1.079 s

三、结论

- JSON 解析约 200 MiB/s，是第一版的瓶颈；跳过不可能有 cwd 键的行之后约 1.3–1.6 GiB/s。
- 一行里含有 "cwd" 字样或 \u 转义、却没有顶层 cwd 的记录仍会被解析；整份文件全是这种行时退回第一版的速度
  （50 MiB 约 0.25–0.3 s，只读一遍）。
- 没有设行数、字节数或文件数的上限，也没有加缓存。最终实现里没有到秒级的数字。
