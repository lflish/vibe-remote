合并前建议知道的已知问题

这一版都没有修。第 1 条是开 PR 之后的复验里验证者判「拦」的，你 2026-11-23 决定记为已知限制、先合并；其余几条验证者没有拦。

  1. tmux 的 socket 路径被换掉时，daemon 会以为会话都没了。tmux 回答「这个 socket 上没有 server」时，daemon 不核对它的会话所在的 tmux server 是否还活着。那个 server 还活着、socket 路径却被换成没人监听的 socket 或文件时（清理脚本、另一个抢同一路径的 tmux），会话从侧边栏消失、同一段 claude 对话可能被再开一次，里面还有活会话的 worktree 可以被删掉。条件少见，后果重。合并后第一个修。（evidence/verdict-3b/；decisions.md c14）
  2. 改名时直接点另一个会话，基本每次都要点两下。daemon 在本机或同一局域网、用鼠标点时，24 次里 24 次没有切换；名字会保存，接着打的字不会进任何地方，再点一次或按回车就切过去。daemon 较远（往返多 30 毫秒以上）或按得很轻时不出现。对话模式那边也有。合并后优先修。
  3. 侧边栏内容正在变化的那一瞬间，点击可能丢。后台有两个对话会话在跑时，单击丢约 5.6%、双击约 2.8%；机器概览页上的按钮安静时也丢约 2.8%（107 次丢 3 次）。内容没变时已经不丢（322 次真实操作 0 丢失）。
  4. 机器概览页的「最近会话」里看不到刚建的对话会话。对话会话的创建时间是 UTC、终端会话是本地时区，排序时对话会话等于早了 8 小时。这是对话模式带来的，不是这个需求引入的。
  5. 侧边栏对已结束的对话会话没有任何标记，要点开才知道。
  6. 创建 worktree 时仓库的钩子以 128 或 129 退出，会留下一个残留的 worktree，同名重试前要先清掉。常见的钩子失败（例如找不到 git-lfs）已经不留残留。
  7. 对话模式的已知问题在新侧边栏上同样存在：权限卡片一出现就拿走键盘，而单个数字键就是回答（见 PR #14 的说明）。

兼容与升级

  • 协议 3 → 4：多一个 attach 字段 worktreeName 和五个 REST 端点（项目列表、移除项目、worktree 预检 / 状态 / 删除）；所有服务端发给客户端的帧与协议 3 相同。
  • 删除会话不再清理 worktree 和分支，删 worktree 是侧边栏里单独的操作。
  • 桌面端和 daemon 要一起升级，先升 daemon。只升一边时降级工作、不报错：新桌面端连旧 daemon 时「新建 worktree」「删除 worktree」置灰并提示升级，没有会话的 worktree 不显示；旧桌面端连新 daemon 时原有功能照常。注意：新桌面端连着旧 daemon 时，旧 daemon 删除 Worktree 模式的会话仍会在工作区干净时连 worktree 和分支一起删（确认框上写明了），这种状态不要久留。
  • state_dir 里多一个 projects.json（项目清单和 vibe-remote 自己建的 worktree）。没有新增配置项，没有要手工迁移的数据；升级前的会话和旧 Worktree 模式建的 worktree 自动归到项目下。
  • git 版本：推荐 2.36 及以上；2.31–2.35 可用，但路径带换行的 worktree 不会列出；低于 2.31 不支持（Debian 11 的 2.30、Ubuntu 20.04 的 2.25 要先升级 git）。daemon 不检查版本。
