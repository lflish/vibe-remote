# 代码评审各条意见的裁决（project-worktrees @ e278f87）

三份评审全文在同目录：`review-go.md`（daemon 侧，9 条 + 5 条可维护性 + 2 条待验证）、`review-desktop.md`（桌面端，11 条 + 3 条待验证）、`review-crosscut.md`（横切面，14 条）。没有「严重」问题。

处理规则（dev-review 第 3 步）：
- **明确错误**：先写能复现它的测试并确认失败，再修，再跑测试；每个修复单独提交，`fix:` 开头，提交信息写明现象。
- **取舍**：按下面的裁决做，记口味型 `d<n>`。
- **待验证项**：先做评审者写的最小实验（单元或集成层面做得了的）。确认了就按明确错误修；排除了写一句；做不了的原样留给 dev-test。
- 评审意见核实后是错的，可以不采纳，写一行理由。
