# 机器工作台与 Worktree Session 设计

日期：2026-08-05
状态：已确认

## 目标

1. 将当前居中的机器概览卡替换为参考 Claudette 的方案 A“机器工作台”。
2. 创建 Session 时支持两种模式：
   - `normal`：在原目录运行，保持现有行为。
   - `worktree`：服务端自动创建隔离 Git worktree，并在其中运行 Claude。
3. 保持 PTY 纯字节透传，不解析 Claude 输出。

## 机器工作台

点击侧边栏机器名后，右侧显示完整页面，而不是浮动卡片。

### 页面头

左侧显示：
- `Machine workspace`
- 机器名
- `addr:port`
- 默认工作目录
- tmux 是否启用

右侧显示：
- `Manage`
- `+ New session`

### 状态摘要

三个轻量统计项：
- 该机器的会话总数
- 当前客户端已连接的 SessionView 数
- 连接类型：地址为 loopback 时显示 `Local`，否则显示 `Remote`

不解析 Claude 输出，也不推导 Claude 内部状态。

### 最近会话

显示最近 3–5 个会话：
- 名称
- 实际 workdir
- Session 模式（Normal / Worktree）
- 本地存在 SessionView 时显示 `Running`，否则显示 `Remote`
- 点击进入现有终端

完整会话列表仍保留在侧边栏。

### 创建入口

工作台中同时展示：
- `Open existing directory`
- `Create isolated worktree`

页面头的 `+ New session` 与两张模式卡调用同一个创建流程，不维护两套实现。

### 视觉语言

- 暖灰背景、白色平面内容块、低对比边框。
- 顶部标题区 + 轻量数据条 + 内容分区。
- 主色只用于选中项和主 CTA。
- 减少大阴影与居中浮层感。
- 终端页面样式不改。

## Session 协议

### AttachFrame

```json
{
  "type": "attach",
  "sessionId": "",
  "cols": 120,
  "rows": 40,
  "workdir": "/home/user/repo/packages/api",
  "mode": "worktree",
  "flags": []
}
```

新增字段：

```ts
type SessionMode = 'normal' | 'worktree';
```

- 不传 `mode` 时默认 `normal`，保持旧客户端兼容。
- `mode` 只对新建 Session 有效。
- 客户端仅传意图，不运行 Git 命令。

### ReadyFrame / SessionInfo

```ts
interface SessionInfo {
  id: string;
  title: string;
  workdir: string;
  created: string;
  mode: SessionMode;
  sourceWorkdir?: string;
  sourceRepo?: string;
  branch?: string;
}
```

ReadyFrame 同步返回上述模式和 Git 元数据，让新建 Session 的客户端立即得到权威结果。

## Worktree 创建流程

用户可选择仓库根目录或仓库内任意子目录。

1. 用 `allowed_roots` 校验用户选择的源目录。
2. 执行 `git -C <selected-dir> rev-parse --show-toplevel` 自动发现仓库根。
3. 用 `filepath.Rel(repoRoot, selectedDir)` 计算相对子目录，并拒绝越出仓库的结果。
4. 自动生成：
   - 分支：`vibe/<session-id>`
   - Worktree 根：`<repo-parent>/<repo-name>-worktrees/<session-id>`
   - Session workdir：`<worktree-root>/<relative-subdir>`
5. 执行：

   ```bash
   git -C <repo-root> worktree add -b vibe/<session-id> <worktree-root> HEAD
   ```

6. 验证映射后的 Session workdir 存在且为目录。
7. 在该目录创建 Runner、tmux 和 Claude。
8. 若 Git 创建成功但 Runner 启动失败，立即执行安全回滚：删除 worktree，再删除自动分支。

源仓库未提交修改不会进入 Worktree；创建基线固定为源仓库当前 `HEAD`。

## 元数据与重启恢复

Tmux 继续是 Session 单一事实来源。Worktree 元数据写入 tmux 用户选项：

```text
@vibe_remote_mode
@vibe_remote_source_workdir
@vibe_remote_source_repo
@vibe_remote_worktree_root
@vibe_remote_branch
```

`liveTmuxSessions()` 的批量格式扩展为一次读取这些字段。服务端重启后可恢复：
- 实际工作目录
- Session 模式
- 源目录
- Git 仓库根
- Worktree 根
- 自动分支

Normal Session 的 `mode` 缺失时按 `normal` 恢复。

## 安全删除

### Normal Session

保持当前语义：删除 tmux/Claude Session。

### Worktree Session

1. 杀掉 tmux/Claude，停止继续写入。
2. 执行 `git -C <worktree-root> status --porcelain`。
3. 工作区干净：
   - `git -C <source-repo> worktree remove <worktree-root>`
   - `git -C <source-repo> branch -D <branch>`
   - 尝试删除已经为空的 `<repo-name>-worktrees` 父目录
4. 有未提交修改：
   - 不删除 Worktree
   - 不删除分支
   - HTTP DELETE 返回 `409 Conflict`
   - 返回 `worktree_preserved` 错误代码、保留路径和分支
   - 客户端告知 Session 已停止，但工作成果已保留

必须先停止 Claude 再检查最终状态，避免检查后 Claude 又写入造成数据丢失。

### 删除幂等与部分失败

- Tmux 已不存在但 Worktree 元数据仍可恢复时，允许继续清理。
- Worktree 已被用户手动删除时，跳过目录删除并继续尝试删除自动分支。
- 分支被用户手动删除时，视为已清理。
- Git 命令异常时保留资源并返回明确错误，不执行强制目录删除。

## 创建窗口

现有目录选择器扩展为 Session 创建窗口：

1. 选择远程目录。
2. 选择 `Open existing directory` 或 `Create isolated worktree`。
3. 选择 Claude flags。
4. Worktree 模式显示：

   ```text
   Repository root will be detected automatically.
   Branch and worktree paths are generated by vibe-remote.
   ```

5. 提交后通过 AttachFrame 创建。

Normal 模式不要求 Git 仓库；Worktree 模式的 Git 错误在终端创建前展示为用户可见错误。

## 错误处理

- 非 Git 目录：`not_git_repository`。
- Git 不可用：`git_unavailable`。
- 分支或 Worktree 路径冲突：`worktree_conflict`。
- 映射子目录不存在：`worktree_subdir_missing`。
- 未提交修改阻止清理：`worktree_preserved` + path + branch。
- Attach 创建失败时 WebSocket error 帧包含可读消息；结构化错误代码可作为 error 帧的可选字段加入，旧客户端仍读取 message。

## 代码边界

### 新服务端组件

新增 `vibe-remoted/internal/session/worktree.go`，集中负责：
- Git 仓库发现
- Worktree 创建
- 回滚
- 状态检查
- 安全清理

Manager 负责 Session 编排，不把 Git 命令散落在 WebSocket handler 或 Runner 中。Runner 仍只负责 PTY/tmux 生命周期。

## 验证

### 服务端测试

- Normal 创建行为完全兼容。
- Worktree 从仓库根创建。
- 从仓库子目录创建并映射相对路径。
- 非 Git 目录失败且不产生 Session。
- Runner 启动失败后 Worktree 和分支回滚。
- 干净 Worktree 删除。
- 有未提交修改时保留并返回冲突。
- 重启 reconcile 从 tmux 恢复 Worktree 元数据。

- 运行 Electron，机器工作台视觉结构与方案 A 一致。
- Normal 模式在原目录启动 Claude。
- Worktree 模式创建同级目录和 `vibe/<session-id>` 分支。
- 切换机器概览和终端不销毁已有 SessionView。
- 删除干净 Worktree Session 后目录和分支消失。
- 制造未提交文件后删除，Session 停止、Worktree 保留、UI 展示保留路径。
